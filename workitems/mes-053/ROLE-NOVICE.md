# MES-053：半導體新手工程師視角

日期：2026-09-13。角色是審查視角，並非真人學員試用結果。本報告只讀現有網站原始碼與專案規則；未執行瀏覽器點擊、手機或視覺可讀性測試，不給品質分數。未修改網站。

## 核心判斷

網站已有相當好的單課材料，特別是實物對資料、同一個 Lot 的情境、操作後保留事件與拒絕原因。但新手缺少一個能回答「我現在學到哪一層、還缺什麼、下一步去哪裡」的全站課程骨架。局部新增返回按鈕改善的是瀏覽歷程，尚不能取代課程先後與概念依賴。ER 的完整性應保留，但完整 ER 不適合作為第一次學習時必須自行選路的起點。

## 現況證據與新手負擔

| 現況證據 | 新手面臨的問題 | 建議 |
|---|---|---|
| `index.html:18–43`：首頁直接是第一課，側欄列第二、三、四部分與 ER，第一節又有整合 ER 入口；未見全站課綱與先備說明 | 首頁既像課程首頁，又像第一課。新手難以知道所有教材包含什麼、哪些必修、何時需要 ER | 增加全站「開始學習」總覽；舊第一課保留連結，入口只給明確的開始與繼續 |

| `er-navigation.js` 已提供 ER 返回、瀏覽路徑；`er-return.js` 以 ER token 回到原主詞 | 已有返回功能，不能再說完全沒有。但來源返回、上一課、沿線上一點是三種不同的「上一個」 | 維持功能，統一命名：「返回剛才主題」「上一課」「沿關係上一點」，並把課程所在位置固定顯示 |

以上是靜態結構推論；「難找」等學習效果仍應以後述任務測試確認。程式長行包含多個 DOM 區塊，行號只供定位。導覽證據已依主代理的執行時核對補查 `course-extension.js`；後續審查須追查動態增補與覆寫，不可把基底模板當成最終畫面。

## 建議的新手主線

用同一批 L023 作為貫穿案例，但每章明確標示現在在比較「實物、定義、當前狀態、事件歷史或預測」。不要強迫所有獨立教材變成同一條事件鏈，例如 RQHBE 不是必經順序、ER 線不是流程箭頭。

1. **先認出人正在管理什麼**：Fab、Wafer、FOUP、Slot、Lot。用單 Lot／多 Lot 同 FOUP 對照，學員能說出身分、位置、歸屬。
2. **這批貨應該怎麼做**：Product／PART、Flow／Route、Module→Stage→Step，Lot 是流程的執行者。第一輪只保留能解釋當前站點的深度，進版放在後續。
3. **從等待到加工**：機台、Load Port、Chamber、Recipe／PD、可用機台、預派、實際開工、RQHBE。先比較預派與進機，再介紹資格控制細節。
4. **貨怎麼被搬過來**：Stocker、OHT、OHB、BMIR／RTD、Port占用，Macro／Micro 搬送歷史。明確和 Lot 過站分開。
5. **事情發生過什麼**：批貨歷史、Move、Lot Step、FOUP 內容物歷史、拆合批。學員用一條帶時間的案例區分事件與狀態摘要。
6. **什麼規則會讓它停下或改路**：Hold、Future Hold、Product Hold、QTime、Sampling／SRTS、Rework／Sub Route。逐題學，不一次列出十多個縮寫。
7. **資料能不能回答現在的問題**：來源、更新時間、当前／歷史／固定時點快照。引入每天 07:20、每小時與最近更新的差異；查資料前就問時間，不等所有 KPI 教完才補。
8. **認識管理視角與報表**：Bay／管理課別、一般機群／虛擬機群／Chamber 分群、KER、WPH 與預計到站。先教指標用途與資料範圍，未確認的公式不補造。
9. **第一次自己沿 ER 找資料**：由「查 L023 曾過哪些站」這類已學會的問題開始，找實體→看關係→看來源→判斷能否回答；之後再進完整圖與進階查詢。

此處是概念編排，不要求一次新增九個大 HTML，也不主張刪除完整 ER。第 2 章若一次太長，Module／Stage 詳情可次層展開；第 7 章的最小時間觀念要從第 3 章就出現，後面再集中深化。

## 每一課的固定閱讀契約

- 進入先看到「本課要回答的工作問題」「需要先會什麼」「學完能做什麼」。不要求先知道資料表名稱。
- 主線依序：情境→一张针对该概念的图→关键区别→一次操作或判断→解释答案与证据→下一课。
- 技术层放在明确的「查资料」区：表名／关系键／时间范围／来源限制。不要把表名塞进每个教学图大标题。
- 同一名词在不同对象不同义必须就地说明：Port UP／LOST与设备 UP／LOST；MES Step与Recipe Step；Lot、FOUP、Wafer状态。
- 字典可就地展开后关闭，保留当前阅读位置；产品／PART、Flow／Route／mainpd_id等以同义入口可找到同一概念。首次出现只教必要名称。
- 完整 ER 为参考工具；主线提供「在 ER 查看本课关系」并允许原路回来。返回必须保留案例、题目、段落与阅读进度。

## 优先顺序

**P0：先修课程骨架。** 建全站课纲、统一课程当前位置／上下课／继续学习；把第 2 部分所需最小 Flow知识提前；清理同时出现的 ER 入口语义。此阶段复用现有图文，不应先投入一批新插画。

**P1：再修认知衔接。** 为跨主题建立短桥接页或导入段；统一同义词／缩写；建立案例概念对照；把最新厂内定义同步回旧课程主线，而非仅更新 ER 侧栏。具体需逐主题核对，不以单个 ER topic 已更新判定全站一致。

**P2：再做完整学习与复习体验。** 保存学习位置、可跳过已会的诊断题、按错因推荐回看；增加来自现场问题的综合题。不能用「点过页面」当作「已经理解」。

## 建议的新手验收任务

找 3–5 位未参与网站设计的人作为探索性试读；这只能发现问题，不足以证明整体课程有效。记录他们的口述、点击、迷路点与错误解释，不以界面功能 PASS 代替学习验收。

| 任务 | 要观察的结果 |
|---|---|
| 首次打开网站，决定从哪里开始，并说出接下来两课 | 能在没有导师指路下说明主线；不要靠试点每个菜单 |
| 解释同一 FOUP 中两个 Lot、不同 Wafer／Slot | 能分清容器、成员和管理身份，且换载具不自动等于拆批 |
| 看到「已预派」「Port有货」「Lot R」三笔资料 | 说出各对象、发生层次与可证明的事实，不能合并成已完成加工 |
| 在一课中打开 ER、选择关联主题、放大图，再回来 | 回到同一课段与案例状态；能区分来源返回和下一课 |
| 查询 Lot 的过站历史并说出为什么不查 MCS搬送历史 | 先从业务问题选来源，再用表名；说明事件语义差异 |
| 比较最近更新、每小时历史、每天07:20快照 | 说明时间含义与不能据此认定目前状态；无需计算 EFF |
| 中断学习后重新打开；手机从深链接进入某主题 | 能找到继续学习／所属课程／下一步，不依赖此前 ER session token |

实施前先测现站形成基线；原型后以相同任务比较。成功标准应由导师确定，至少包含正确解释、任务完成、必要提示次数与返回后状态保留。未实际收集的数据不填分。

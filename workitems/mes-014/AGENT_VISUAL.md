## 必修缺口

1. **區分「完整關係範圍」與「可讀局部」。** 當整段fit會低於可讀字級時，顯示其為路徑概覽，提供「沿線閱讀」下一端／下一關係控制，在同一張圖上平移，以至少約14–16px顯示目前物件或關係文字；仍用持續高亮及小型路徑標示交代兩端。不要只將所有標籤放進圖外清單，也不要重新排圖。
2. **預設 load 手機不能只有6px文字。** 這是第一個會看到的教學畫面。保留關係全貌縮覽，同時讓目前菱形與端點可以一步定位到可讀大小，選中長路徑自動提供此模式。
3. **檢查長邊佈局代價。** FRLOT到Flow跨越許多中間分支，使1440寬仍只有7px。可以在製圖階段縮短最重要跨區邊、調整核心相鄰關係；不必為了把圖完整塞進畫布犧牲文字。任何改排後需重新檢查穿線與原邊保留。
4. **手機減少圖與解釋往返距離。** 可將當前關係名與一行物理意義保持在圖旁／圖下，詳細來源仍在展開區。避免需捲過近600px微小圖才能知道正在看什麼。

原始SVG本身是可縮放向量，未發現文字永久不可到達的證據；此次不把預設小字錯說成「資料遺失」。然而預設聚焦不可讀是明確交付缺口，因此總分不達>90。本報告不是使用者驗收，也不應與其他agent高分平均後掩蓋此問題。

### 新的實看／實測證據

實際看 `tests/evidence/mes-014/v2/` 的 `load-390.png`、`move-390.png`、`flow-1440.png`、`location-390.png`：目前閱讀節點文字明顯可讀。load能看清装載菱形與FOUP；location菱形左右可能超出視窗，但內文完整可讀；move相鄰歷史表部分出框，界面已說明用上／下一點定位。未把出框的相鄰節點誤列為資料遺失。

另外重新以Playwright開啟現行localhost網站，兩種寬度1440／390各測 load、move、flow、location、recipe，對每條路徑的每個節點逐點定位：

- 1440的load、recipe全段可用111%顯示；move、flow、location轉90%沿線閱讀。
- 390五條路徑均轉90%沿線閱讀。逐點模式文字為18 CSS px。
- 逐一檢查各目前節點的所有text bounding rect都在canvas內，這五條路徑兩種寬度**未發現當前節點文字被裁切**。
- 每条路徑按「下一點」到2／N，再按「上一點」回1／N，符合顯示與實際定位。
- 兩種寬度直接點裝載菱形後，顯示兩組實際edge-pair；按ArrowRight後viewBox改變。
- 以CDP dispatchTouchEvent模擬兩指由70px拉開至130px，兩種寬度viewBox均改變。這是瀏覽器觸控模擬通過，**不是實機觸控測試**。

沒有把小字問題以縮成孤立小卡片解決；仍是同一張真實SVG、原位置及關係保持。舊的可讀性主要缺口已實際修正。上述91分僅支持這種「完整大圖＋同圖沿線閱讀」的互動交付形式，不宣稱整張圖縮在手機一屏即可讀，也未獨立逐條目視128邊。

# MES-013：整合 ER 畫法討論

狀態：使用者要求 Multi-agent 思考畫法，本輪僅審查／設計，未重畫或修改網站。

三位獨立 agent：merge_rules（實體與關係合併）、er_layout（原圖語法及布局）、er_critic（資訊流失及驗收）。共同核對七張來源及MES-012整合內容；一致認為20主題圖改變了ER拓撲，不能作為使用者要求的整合ER交付。保留其歷史紀錄，不再宣稱已滿足整合ER需求。

## 核心決策

合併同一資料對象的重複出現，保留不同關係；不把多個資料對象合成主題卡。矩形、關係菱形、鍵值中介及屬性註記保留來源語法。FRCAST_LOT等關係表可維持原圖菱形並保留表名；底層型別和圖面形狀分開。原圖本身是混合記法，不假装已有完整PK/FK/基數。

- FRLOT、FRCAST、FREQP 作中央核心；上方Flow／Part／PD／Recipe；下方事件與搬送；設備子資源與分析表在對應外側。
- 區域背景只協助布局，不是新節點、不參與連線。取消主圖上的教學比較線。
- 相同完整資料表識別才作可靠合併；省略schema是別名候選，不能默默確認同表。中文同義不足以合併。
- SYSTEMKEY、EQP_ID等同名欄位依所属表／原圖上下文保留，不合併成全域實體。不同SYSTEMKEY尤其不能接成一個共享鍵。
- KER_WIP_BT≠FRLOT；KER_EQP_STATUS_BT≠FREQP；Siview.Port與FRPORT不直接合併；CSFRPREDISPATCH與CSFHPREDISP分開。
- 只在端點、語意、鍵及角色相同時去重邊；預派、位於、預到等平行關係保留。
- 圖號只存在詳情來源面板，主圖不顯示。

## 題目如何結合物理意義

同一張圖固定位置。聚焦只高亮既有節點與關係，不重新排列，也不新造線。物理意義在點選關係時顯示，例如裝載關係回答哪個FOUP裝哪批，不能證明Wafer進Chamber。手機定位一段矩形—菱形—矩形的完整關係，避免只顯示孤立節點。

## 第一個原型範圍

FRLOT、FRCAST、FREQP、Port／Chamber及以下原圖路徑：

- Lot — 放在／FRCAST_LOT — FOUP
- Lot — EI在／FREQP_LOT — Port
- Lot — 預到／FRLOT_EQP — EQP
- FOUP — 位於／CSFHDOPHS — EQP
- FOUP — 預派／CSFRPREDISPATCH — EQP

先實看此中央片段是否保留物件、關係與關係表，再擴充流程配方、事件、WIP與統計。第一個原型不把未確認的Port同義映射當確定關係。

## 驗收標準

每個來源節點與128條原始邊都需對應到實際圖面或有明確去重證據；只放進JSON不代表圖面保留。抽取原圖完整路徑，在大圖上應能沿線走完。表名／關係表／鍵需可見，不能藏在概念卡內。未知基數、Join、實際Recipe執行不新增。題目與全圖共用同一拓撲及座標；關係交叉不可看成連接。主圖來源編號不得恢復。
